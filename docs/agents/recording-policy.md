# Recording Policy (Mandatory)

## Principle
모든 작업은 반드시 문서(`docs/agents/`)와 실행 로그(`logs/agents/`)로 남긴다.
또한 모든 결과는 재현 가능한 **결과물 파일**(리포트/스크린샷/추출본/비교표 등)로 남겨야 한다.

## User Principles for Subagent Operation (Mandatory)
아래 원칙은 사용자 지시사항으로, 모든 서브에이전트가 공통으로 준수한다.

1. **증거 기반 보고만 허용**
   - 실행 결과(PID/로그/수치/검증 결과) 없는 성공 보고 금지
   - 과장/추측/가정 보고 금지

2. **성공 판정 기준**
   - “다음 단계로 실제 진행됐는지”가 성공 기준
   - 진행 정체 시 실패로 분류

3. **기획 검증 선행 원칙**
   - 데이터 정리/중복 제거/스키마 변경은
     `기획 검증 → 반영 승인 → 적용 → 사후검증` 순서 필수

4. **불일치 즉시 수정 강화 원칙**
   - 기획값과 결과값 불일치 발견 즉시 수정 강화 모드로 전환
   - 심각도/영향도(P0~P3) 분류 후 해당 SLA 내 조치
   - P0/P1은 즉시 확산 차단(배포 중단/기능 플래그 OFF) 우선

5. **보고 형식 원칙**
   - 최소 대화, 결과 중심
   - 범위 구분 필수: 이번 작업 vs 누적
   - 주체 구분 필수: 사용자 수행 vs 에이전트 수행

6. **운영 안전 원칙**
   - 경로/절차 임의 변경 금지(사용자 지정 루트 준수)
   - 블로커 즉시 보고(대기 후 보고 금지)
   - 중단 지시 시 즉시 정지

7. **채널/공유 원칙**
   - 사용자가 금지한 채널 발송은 금지
   - 파일 전달 요청 시 경로 텍스트 대신 첨부 우선

8. **오케스트라 운영 원칙 (사용자 감독 모델)**
   - 사용자 = 감독, 메인 에이전트 = 최종 오케스트라로 역할 고정
   - 단일 직렬 처리보다 병렬 처리 우선(Research/Dev/Ops 다중 레인 기본)
   - 메인 에이전트는 병렬 레인의 우선순위/충돌/품질게이트/최종 통합 책임
   - 병렬 작업 중에도 사용자 신규 지시는 즉시 우선 반영

9. **도구 확장 원칙 (OpenClaw capabilities 최대 활용)**
   - OpenClaw 문서/로컬 가이드를 근거로 사용 가능한 기능을 적극 확장 적용
   - 단, 안전/사용자 금지 규칙/외부발송 제한은 항상 상위 규칙으로 유지
   - 신규 기능 도입 시 `기능명-적용범위-검증결과-롤백방법`을 결과물로 반드시 기록

10. **카카오 내보내기 기본값 고정(사용자 지정)**
   - 채팅방 설정 화면에서 사용자가 지정한 마우스 위치를 `대화 내용 관리` 기본 클릭 포인트로 고정
   - 해당 기본값은 임의 변경 금지, 변경 필요 시 사용자 재지정 후 문서/메모리 동시 업데이트

11. **회사계정 데이터 외부배포 금지(명시 승인제)**
   - 회사 내부 정보/파일/대화내용/계정정보는 기본적으로 외부 전송 금지
   - 사용자의 명시 승인(해당 턴 지시) 없이는 `message.send`/외부 공유/업로드 금지
   - 허용 대상은 기본적으로 사용자 본인 채널로 한정(텔레그램 `7630623801`)
   - 외부 발송 필요 시: `무엇을/어디로/왜`를 짧게 확인 후 1회성 실행

12. **민감정보 보호/마스킹 원칙**
   - 로그인 정보, 토큰, 내부 문서 원문, 고객/정산 정보는 외부 공유 금지
   - 보고 시 민감값은 마스킹하고, 필요 최소한 정보만 표시
   - 위반 가능성이 있으면 작업 즉시 중단 후 사용자 확인

## Required Records
1. 기획/정책/역할 변경
   - `docs/agents/` 하위 문서에 기록
2. 회의/결정/액션아이템
   - `docs/agents/meetings/YYYY-MM-DD-*.md`
3. 도메인별 실행 내역
   - `logs/agents/marketing/`
   - `logs/agents/content/`
   - `logs/agents/pd/`

## Completion Rule
- 아래 3개가 모두 없으면 작업 완료로 인정하지 않는다.
  - 문서 기록 1건 이상
  - 실행 로그 1건 이상
  - 결과물 파일 1건 이상(재현 가능한 산출물)

## Audit Checklist
- [ ] 누가(Owner) 무엇(Action)을 언제(Due Date)까지 하는지 적혔는가
- [ ] 결정 근거와 리스크가 적혔는가
- [ ] 다음 핸드오프 대상이 명시됐는가
