## 4) runbook-controller policy 연동 강화 + PASS/FAIL 증거 엄격화

### 구현
- `automation/controller.py`
  - evidence 필수 필드 강화:
    - `step`, `status`, `checks`, `failed`, `proof_ts`
  - 무결성 검사:
    - `status=PASS`인데 `failed!=0`이면 FAIL 처리
    - `status=FAIL`인데 `failed==0`이면 FAIL 처리
  - 자동 모드 전환:
    - 연속 실패 >=2 → `downgrade`
    - 연속 실패 >=5 → `hold`
  - executor 분기:
    - normal: `executor_command`
    - downgrade: `executor_command_downgrade`
    - hold: 실행 중단
- `automation/policy.json`
  - `executor_command`, `executor_command_downgrade`, `downgrade_after_failures`, `hold_after_failures` 추가
- `scripts/simulate_ops_runbook.py`
  - `--mode {normal,downgrade}` 지원
  - strict evidence 포맷 출력
- `docs/kakao-openchat-export-runbook.md`
  - controller 연동 규약/모드전환 규칙 문서화

### 실행 증거
- `python3 scripts/simulate_ops_runbook.py`
  - `RUNBOOK_SIMULATION status= PASS mode= normal`
  - `checks= 4 failed= 0`
  - `NEXT_STEP_OK`
  - `EVIDENCE:{"step":"runbook_simulation","status":"PASS","checks":4,"failed":0,...}`
- `python3 scripts/simulate_ops_runbook.py --mode=downgrade`
  - `RUNBOOK_SIMULATION status= PASS mode= downgrade`
  - `checks= 2 failed= 0`
  - `NEXT_STEP_OK`

## 리스크
- 텔레그램 dedup state 파일이 손상되면 중복방지 정확도 저하 가능.
- 수집기 safety stop 기준은 현재 고정 상수(환경별 튜닝 필요).
- 부하벤치는 ASGI in-process 기준으로, 네트워크/실서버 오버헤드는 미반영.
- controller `hold` 해제는 현재 수동(state 수정) 절차 필요.
