# Priceit Starter 프론트/대시보드 기획안

> 대상: `web/dashboard.html` 기반 운영 대시보드 고도화
> 목적: 운영자가 **이상 상황을 놓치지 않고(경고/실패 가시화)**, **확인→조치→재실행**을 짧은 동선으로 수행하도록 UI/UX를 정리한다.

---

## 1) 설계 원칙

1. **모바일 우선(Mobile First)**
   - 최소 화면(360px)에서도 핵심 상태(경고 수, 실패 수, 최근 실패 1건, 재실행 버튼) 노출
2. **운영 우선(Ops First)**
   - 데이터 탐색보다 먼저 “지금 조치할 것”을 앞단에 배치
3. **드릴다운 일관성**
   - 어떤 진입점(시간순/유형순/룸순)에서도 동일한 상세 패널 구조 제공
4. **실패 명확성**
   - 특히 “**다음 코스 미진입**” 상태를 실패로 명시하고 별도 배지/필터 제공

---

## 2) 정보구조(IA): 시간순 / 유형순 / 룸순

대시보드 내 3개 기본 뷰를 탭으로 제공한다.

## A. 시간순(Time Feed)
- 목적: 최신 이상 상황을 빠르게 파악
- 기본 정렬: `event_at DESC`
- 기본 블록:
  - 경고/실패 요약 배너
  - 실시간 이벤트 피드(무한 스크롤 또는 페이지)
  - 최근 실패 10건(고정 섹션)

## B. 유형순(Type View)
- 목적: 실패/이상 패턴 분류 확인
- 그룹 기준 예시:
  - `재고`: 품절, 재입고
  - `가격`: 인상, 인하, 변동 없음
  - `파이프라인`: 파싱 실패, 알림 실패, **다음 코스 미진입**
- 각 그룹 카드에 건수 + 증감률(전 기간 대비)을 노출

## C. 룸순(Room View)
- 목적: 룸별 운영 상태/건강도 파악
- 룸 카드/테이블 필드:
  - 룸명
  - 최근 메시지 시각
  - 최근 이벤트 시각
  - 1h 이벤트 수
  - 실패 수
  - 상태 배지(`정상` / `주의` / `중단`)

---

## 3) 화면별 컴포넌트 설계

## 3.1 공통 레이아웃
- 상단 App Bar
  - 타이틀, 마지막 동기화 시간, 새로고침 토글(자동/수동)
- 글로벌 상태 바
  - `전체 경고`, `실패`, `다음 코스 미진입`, `알림 실패`
- 하단(모바일) 탭 네비게이션
  - 시간순 / 유형순 / 룸순 / 작업함

## 3.2 시간순 화면 컴포넌트
1. `KpiStrip`
   - 메시지 수, 이벤트 수, 실패 수, 미진입 수
2. `AlertBanner`
   - 심각도별 배너(critical/warn/info)
3. `EventFeedList`
   - 이벤트 아이템(시간, 룸, 유형, 상태 배지, 신뢰도)
4. `FailureQueuePanel`
   - 실패건만 모은 큐, “조치 필요” 우선순위 정렬

## 3.3 유형순 화면 컴포넌트
1. `TypeSummaryGrid`
   - 유형별 카드, 클릭 시 해당 유형으로 드릴다운
2. `TypeTrendMiniChart`
   - 24h/7d 스파크라인
3. `TypeEventTable`
   - 선택된 유형의 이벤트 목록

## 3.4 룸순 화면 컴포넌트
1. `RoomHealthTable`
2. `RoomStatusBadge`
3. `RoomTimelineMini`
   - 메시지/이벤트 추이(미니 차트)
4. `RoomDetailDrawer`
   - 선택 룸의 최근 실패, 최근 조치 이력

## 3.5 상세/조치(드릴다운) 컴포넌트
1. `EventDetailDrawer`
   - 원문 메시지, 파싱 결과, 실패 사유, 관련 로그
2. `ActionPanel`
   - 확인(ack), 조치 실행, 재실행(retry) 버튼
3. `ExecutionResultToast`
   - 조치/재실행 결과 피드백

## 4) 필터 / 검색 / 드릴다운 UX

## 4.1 필터 UX
- 기본 필터:
  - 기간(최근 15분/1시간/24시간/사용자 지정)
  - 유형(event_type)
  - 룸(room)
  - 상태(status: 정상/경고/실패/미진입)
- 고급 필터:
  - confidence 범위
  - 알림 전송 성공/실패
- UX 규칙:
  - 모바일에서는 Bottom Sheet 필터
  - 선택된 필터 수를 배지로 표시
  - 필터 프리셋 저장(예: “실패만 보기”)

## 4.2 검색 UX
- 통합 검색 대상:
  - 룸명, 상품명, 벤더, 이벤트 키워드
- 검색 입력 즉시 제안(최근 검색 + 상위 키워드)
- 검색 결과는 현재 뷰 컨텍스트 유지(시간/유형/룸)

## 4.3 드릴다운 UX
- 1단계: 요약 카드/배지 클릭
- 2단계: 리스트/테이블에서 항목 선택
- 3단계: 우측 Drawer(모바일은 Fullscreen Sheet)
- 상세에서 바로 조치 가능(컨텍스트 전환 최소화)

---

## 5) 경고 배지와 실패 표시 정책

## 5.1 배지 체계
- `정상`(green)
- `주의`(amber)
- `실패`(red)
- `미진입`(purple/red border) ← **다음 코스 미진입 전용**

## 5.2 “다음 코스 미진입” 정의(운영 관점)
다음 단계 파이프라인으로 상태 전이가 발생하지 않은 이벤트를 의미한다.

예시 조건(초안):
- 이벤트 생성 후 N분 내 `next_stage_at` 없음
- 또는 `stage_transition=blocked` / `rejected` 로그 감지

표시 규칙:
- 이벤트 리스트: 상태 칩 `미진입`
- 요약 KPI: `다음 코스 미진입` 별도 카운트
- 룸 상태: 미진입 반복 시 룸 상태를 `주의` 이상으로 승격
- 실패 큐: 우선순위 상단 배치

---

## 6) 운영자 워크플로우: 확인 → 조치 → 재실행

## 단계 1. 확인(Verify)
- 실패 큐 또는 경고 배너 클릭
- 상세에서 원문/파싱/로그 확인
- 실패 유형 분류: 데이터 문제, 룰 문제, 외부 전송 문제, 미진입

## 단계 2. 조치(Act)
- 조치 템플릿 선택:
  - 파싱 규칙 보정(키워드/패턴)
  - 예외 룰 적용
  - 룸/벤더 매핑 수정
  - 전송 채널 설정 점검
- 조치 실행 시 작업 이력 기록(`who`, `when`, `what`)

## 단계 3. 재실행(Retry)
- 대상 이벤트/배치 선택 후 재실행
- 결과를 즉시 토스트 + 상세 패널 로그에 반영
- 재실행 실패 시 다음 액션 제안(에스컬레이션/임시차단)

## 단계 4. 종료/모니터링(Close)
- 성공 시 상태 `해결`로 전환
- 동일 유형 재발 여부를 30~60분 감시

---

## 7) 모바일 우선 최소 화면(MVP Minimum)

해상도 360x800 기준 필수 컴포넌트만 남긴다.

1. 상단: `전체 경고`, `실패`, `미진입` 3개 카운터
2. 중단: `조치 필요 Top 5` 리스트
3. 하단: `확인`, `조치`, `재실행` 빠른 액션 버튼
4. 필터: 상태 + 기간 2개만 1차 제공
5. 상세는 Fullscreen Drawer 1종으로 통일

제외(후순위):
- 복잡 차트, 다중 비교, 사용자 커스텀 레이아웃

---

## 8) 현재 `web/dashboard.html` 개선 로드맵

현재 상태 요약:
- 단일 페이지 + 5초 폴링
- 요약 카드(메시지/이벤트/마지막 메시지)
- 이벤트 유형/상위 룸 테이블
- 경고/실패/조치 UX 부재

## Phase 0 (빠른 정리, 0.5~1일)
- 코드 구조화: API fetch, 렌더 함수 분리
- 에러 상태 UI 추가(네트워크 실패/빈 데이터)
- 로딩 스켈레톤/갱신 시각 개선

## Phase 1 (운영 가시성, 1~2일)
- 경고/실패 KPI 카드 추가
- “다음 코스 미진입” 전용 카드/배지 추가
- 실패 이벤트 테이블(최근 N건) 섹션 추가

## Phase 2 (탐색성, 2~3일)
- 시간순/유형순/룸순 탭 도입
- 필터(기간/유형/룸/상태) + 검색창 도입
- 행 클릭 시 상세 Drawer 오픈

## Phase 3 (운영 워크플로우, 2~3일)
- 상세 Drawer 내 확인/조치/재실행 버튼 추가
- 조치 이력 패널 및 결과 피드백
- 실패 재실행 후 상태 반영 로직 연동

## Phase 4 (모바일 최적화, 1~2일)
- 360px 기준 레이아웃 리팩터링
- 하단 탭/바텀시트 필터/풀스크린 상세
- 성능 최적화(렌더 최소화, 폴링 조정)

---

## 10) 완료 기준(DoD)

- 운영자가 모바일/데스크톱에서 1분 내 실패 원인에 도달 가능
- “다음 코스 미진입” 건을 별도 식별/필터링/우선조치 가능
- 확인→조치→재실행 동선이 화면 전환 2회 이하로 수행 가능
- 실패 재실행 결과가 즉시 UI에 반영되고 로그에 남음

---

## 부록) 초기 UI 상태 매핑 예시

- 정상: `status=ok` → 녹색 배지
- 경고: `status=warn` 또는 실패 임계치 근접 → 주황 배지
- 실패: `status=failed` → 빨강 배지
- 미진입: `status=next_stage_miss` → 보라/빨강 테두리 배지
