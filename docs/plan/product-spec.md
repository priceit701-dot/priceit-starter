# Priceit 제품 기획서 (OpenChat 수집 → 유형분류 → 알림 → 운영)

## 1) 문제 정의

### 배경
오픈채팅 기반 셀러 커뮤니티에서는 다음과 같은 문제가 반복된다.
- 메시지량이 많아 중요한 판매/재고/가격 시그널을 놓침
- 운영자가 수동으로 메시지를 읽고 정리해 대응해야 하므로 확장성이 낮음
- 셀러는 자신과 관련된 정보만 빠르게 받고 싶지만, 노이즈가 많아 행동 전환이 늦음

### 해결하려는 핵심 문제
1. **탐지 지연**: 중요한 이벤트를 늦게 발견함
2. **분류 부정확**: 메시지 유형(가격변동, 재입고, 공구, 문의 등) 구분이 일관되지 않음
3. **알림 피로도**: 모든 이벤트를 동일하게 알리면 무시율이 높아짐
4. **운영 비가시성**: 어떤 이벤트가 실제 액션/성과로 이어졌는지 추적이 어려움

### 제품 목표
오픈채팅 데이터를 자동 수집·정제·분류하고, 우선순위 기반 알림과 운영 대시보드를 통해
- 운영자의 대응시간을 단축하고
- 셀러의 실행률(확인/액션)을 높이며
- 반복 가능한 운영 루프를 만든다.

---

## 2) 사용자 정의

### A. 운영자 (Admin / Ops)
- 목표: 중요한 이슈를 빠르게 파악하고 팀 대응 품질을 높임
- 주요 업무: 모니터링, 분류 규칙 관리, 알림 정책 튜닝, 품질 점검
- 성공 기준: 누락률 감소, 평균 대응시간 단축, 운영 효율 개선

### B. 셀러 (Seller)
- 목표: 본인에게 영향 있는 정보(가격, 재고, 경쟁 상황)를 적시에 수신
- 주요 업무: 알림 확인, 재고/가격/프로모션 액션 수행
- 성공 기준: 알림 기반 실행 증가, 매출/회전율 개선, 불필요 알림 감소

---

## 3) 핵심 유즈케이스

1. **실시간 이슈 포착**
   - 운영자는 최근 N분 내 급증한 메시지/핵심 키워드를 한 화면에서 확인한다.
   - 기대 결과: 이슈 인지 시간 단축

2. **메시지 유형 자동 분류**
   - 시스템이 신규 메시지를 유형으로 분류(예: 가격인하, 재입고, 공동구매, 문의/클레임).
   - 운영자는 오분류를 수정하며 규칙/모델 성능을 개선한다.
   - 기대 결과: 분류 정확도 및 운영 일관성 향상

3. **우선순위 알림 발송**
   - 셀러별 관심 조건(카테고리, 키워드, 가격 임계치)에 맞춰 알림 수신.
   - 높은 우선순위는 즉시, 낮은 우선순위는 묶음(배치)으로 발송.
   - 기대 결과: 노이즈 감소 + 실행 가능한 인사이트 전달

4. **운영 회고 및 정책 개선**
   - 운영자는 KPI 대시보드에서 “탐지→알림→액션” 전환율을 확인.
   - 정책(우선순위, 임계치, 분류 사전)을 주기적으로 조정.
   - 기대 결과: 지속적 품질 개선 루프 확립

---

## 4) KPI (북극성 + 운영지표)

### 북극성 지표 (North Star)
- **알림 기반 실행 전환율** = 알림 수신 후 24시간 내 유효 액션 발생 비율

### 핵심 KPI
1. **탐지 지연시간 (TTD)**: 메시지 발생 ~ 시스템 인입 완료 (p95)
2. **분류 정확도 (Macro-F1)**: 유형분류 품질
3. **고우선 알림 정밀도 (Precision@High)**: 높은 우선순위 알림의 유효 비율
4. **알림 확인율**: 수신 후 X시간 내 확인 비율
5. **운영 대응시간 (TTR)**: 운영자가 이슈 인지 후 조치까지의 시간
6. **노이즈율**: 사용자 피드백 기준 “불필요 알림” 비율

### 목표 예시 (MVP 8주)
- TTD p95 ≤ 5분
- 분류 Macro-F1 ≥ 0.78
- Precision@High ≥ 0.85
- 알림 확인율 ≥ 55%
- 노이즈율 ≤ 20%

## 5) 기능 범위

### MVP (필수)
1. **수집 파이프라인**
   - 오픈채팅 메시지 주기 수집
   - 중복 제거(메시지 해시/시간창 기반)
   - 기본 정규화(시간, 작성자, 본문, 채널)

2. **유형분류 엔진 v1**
   - 룰베이스 + 키워드 사전 기반 분류
   - 미분류/불확실 케이스 “검토 필요” 큐로 이동
   - 운영자 수동 정정 UI(또는 운영 스크립트)

3. **알림 엔진 v1**
   - 우선순위(High/Medium/Low) 결정
   - High: 즉시 발송
   - Medium/Low: 15~60분 배치 요약 발송
   - 셀러별 구독 조건(키워드/카테고리) 적용

4. **운영 대시보드 v1**
   - 수집량, 분류결과, 알림 발송량/확인율, 오류율
   - 일간 품질 리포트 자동 생성

5. **기본 운영 정책**
   - 알림 우선순위 정책 적용
   - 데이터 품질 경고(누락률, 지연, 중복률)

### Phase 2 (확장)
1. ML 기반 분류 고도화 (문맥 분류, 액티브 러닝)
2. 셀러 개인화 점수(관심도/행동 기반 우선순위)
3. 멀티채널 알림(텔레그램/문자/앱푸시) 오케스트레이션
4. A/B 테스트 프레임워크 (알림 빈도/문구/타이밍)
5. 반자동 운영 코파일럿 (이슈 요약·권장 액션 제안)

---

## 6) 실패 기준 (Gate)

다음 코스(다음 단계 개발/확장) 미진입 조건을 **실패**로 정의한다.

### 미진입(실패) 조건
- MVP 운영 4주 시점에 아래 중 2개 이상 미충족:
  1. 분류 Macro-F1 < 0.70
  2. Precision@High < 0.75
  3. 알림 확인율 < 40%
  4. 노이즈율 > 30%
  5. TTD p95 > 10분
- 또는 운영팀이 주당 수동 보정 시간 20% 이상 절감에 실패

### 실패 시 조치
1. 범위 축소(유형 수 축소, 고우선 케이스 집중)
2. 규칙 사전 재설계 및 라벨링 데이터 재수집
3. 알림 정책 보수화(발송량 제한, 우선순위 임계 상향)
4. 2주 개선 스프린트 후 재평가

## 7) 데이터 품질 기준

### 수집 품질
- **누락률**: 기준 샘플 대비 ≤ 2%
- **중복률**: 전체 인입 대비 ≤ 1%
- **시간 정합성**: 이벤트 타임스탬프 파싱 성공률 ≥ 99%

### 분류 품질
- **라벨 유효성**: 미정의 라벨 0%
- **모델/룰 일관성**: 동일 입력 재처리 시 라벨 일치율 ≥ 99%
- **검토 큐 SLA**: 불확실 케이스 24시간 내 90% 처리

### 알림 품질
- **전달 성공률** ≥ 98%
- **중복 알림률** ≤ 1%
- **잘못된 타깃 발송(오발송)** 0건 목표

### 운영 품질
- 일간 품질 리포트 자동 생성 100%
- 치명 오류(수집 중단/알림 완전 실패) 발생 시 10분 내 운영자 경보

## 8) 알림 우선순위 정책

### 우선순위 레벨 정의
- **High (즉시)**
  - 가격 급변(예: 기준 대비 ±X% 이상)
  - 재입고/품절 전환
  - 대량 문의/클레임 급증
  - 운영자 수동 플래그 “긴급”

- **Medium (단기 배치)**
  - 반복 출현 키워드 이슈
  - 경쟁사 프로모션 감지
  - 카테고리 단위 유의미 변동

- **Low (요약 배치)**
  - 참고성 정보, 단순 대화성 메시지
  - 즉시 액션 필요성이 낮은 트렌드

### 점수 기반 결정 규칙 (예시)
- Priority Score = (영향도 × 0.5) + (긴급도 × 0.3) + (신뢰도 × 0.2)
- Score ≥ 80: High / 50~79: Medium / <50: Low

### 발송 정책
- High: 즉시 1회 + 재알림 1회(미확인 시)
- Medium: 15~30분 단위 묶음
- Low: 60분~일간 요약
- 사용자 피로 보호:
  - 동일 유형/동일 대상 쿨다운 적용(예: 30분)
  - 일 최대 발송량 상한

### 예외 및 오버라이드
- 운영자 긴급 플래그는 모든 자동 규칙 우선
- 시스템 신뢰도 낮음(불확실 분류) 시 High 금지, 검토 큐 우선

---

## 9) 운영 프로세스 (Ops Loop)

1. **수집 모니터링**: 누락/지연/중복 이상치 감지
2. **분류 검증**: 샘플링 검수 + 오분류 라벨 정정
3. **알림 성과 점검**: 확인율/실행율/노이즈 분석
4. **정책 튜닝**: 우선순위 임계치, 키워드 사전 업데이트
5. **주간 회고**: KPI 달성 여부 및 다음 주 실험안 확정
